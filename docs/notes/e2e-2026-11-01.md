## Findings

1. **`swift test` is flaky on this Mac, and it can pause a lane.** With Command Line Tools only (no Xcode), it sometimes fails with `external macro implementation type 'TestingMacros.TestDeclarationMacro' could not be found`. In lane c it passed, then failed on the next run with no changes. Lane a hit this and paused to ask for `swift package clean`, which did not help; the flag that worked is `-Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing`. This looks like the toolchain and not MetalFlow, but a Swift flow's gate could fail for this reason alone. Cause not established.
2. **A gate's output puts test results before the build log.** Stdout comes first and stderr is appended, so the last lines read "Build complete!" even though tests ran. Reading only the tail makes it look as if no tests ran.
3. **The judge takes gate results on trust.** It said so itself. That is what the flow's prompt asks for, so this is only a note.
