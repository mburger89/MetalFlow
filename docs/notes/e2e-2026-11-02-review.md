# Live end-to-end run — 2026-11-02 — Review node — PASS

First run of the Review node against real agents. Follows `e2e-2026-11-01-open-pr.md`.

Setup: fresh SSH clone of `mburger89/metalflow-e2e` at `origin/main` (3325a11), issue #1, a scratch `METALFLOW_HOME`, `mflow` from `review-node` 2f679dc.

```
mflow launch 1 --flow "E2E Review" --repo <clone>
mflow show <run>
mflow discard <run>
```

The flow: implement ×2 (sonnet, haiku) → `swift test` gate (`fixAttempts: 1`) → Review (sonnet, `fixAttempts: 1`) → judge (sonnet) → pick. To force "changes", the review prompt requires a doc comment whose first line is exactly `/// Compares letters and digits only.`, which the implement prompt does not mention.

Verified:

- Both reviewers asked for changes on the first pass. Each candidate got a commit titled `Fix attempt 1 of 1: <issue title> (<lane>)` with `Review: Review` in its body, and both final versions have the exact doc comment line.
- The gate and the review both reran after the fix, in that order.
- `mflow show` gives `review approved` for a and `review asked for changes` with the findings for b. The judge weighed both, and recommended a over the smaller diff because b still had an open review.
- Review b's remaining findings are about the code. It found a real bug: `("0"..."9").contains($0)` compares `Character`s as strings, so it keeps a digit followed by a combining accent.
- b stayed pickable with its budget used up, and the run stopped at the pick.
- After `mflow discard`: no `flow/*` branches or extra worktrees in the clone, and its `main` is clean at 3325a11. Origin has only `main` and the older PR #2 branch. Issue #1 is open with no comments.

Not run: the app UI for this run, or a pick. Neither reviewer's transcript was searched for a real use of `Bash(git diff:*)`, because `{diff}` gave them the diff, so the allowlist for reviewers is still unproven. A failed or errored review was not produced here either.

## Findings

1. **Reviews and implementers run under the user's own Claude setup, including project memory.** Review a's reply says "The project memory note saying it was missing is stale". Something from outside the prompt reached the agent, and a reviewer could weigh a stale note against the code. It did not change this result. Whether it came from the memory plugin or the resumed session was not checked.
2. **An approving reviewer can still list a problem.** Review a approved while naming a missing test. The approval reads as "good enough", and the text stays in the node's output, but `mflow show` prints findings only when the review did not approve, so this one is not shown.
