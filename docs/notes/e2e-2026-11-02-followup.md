## Verified

- **A.** Flow `Plan → Implement (haiku, haiku) → Gate → Pick`, with Implement's `continuesSessionOf: plan`. `mflow launch` exited 1 with `mflow: Implement and the step it continues have to run in the same worktree: both candidates, or neither.` No run was created.
- **B.** `first` is told `PURPLE-OTTER-LANTERN` in its prompt only and replies `OK`. `second` has no placeholder, and its only wire is `first`'s output. In the saved run file both have `sessionID` aae0af39-4b07-4b65-bf35-03559da45150, and `second` output is `PURPLE-OTTER-LANTERN`. Control (same flow, no `continuesSessionOf`): different session IDs (ae538158… and 470ab927…), and `second` output is `UNKNOWN`.
- **C.** Flow `Input → Implement (haiku, haiku) → Gate → Judge → Pick`. It reached needs-you at pick, recommending a. Then `mflow follow-up <id> implement@a -- Add one more small line…`:
  - `implement@a` kept sessionID 1e5689da-cdf5-4914-8aba-9ca08f4e8c9b before and after.
  - Lane a's branch went from 1af96af to 555efb2, a second commit. `hello.txt` there has the original line plus `A second line, small and clear.`.
  - `gate@a` and `judge` reran, with later `startedAt` and `endedAt` (gate@a ended 04:26:53 then 04:27:23; judge 04:27:00 then 04:27:30).
  - `implement@b` and `gate@b` node records are byte-identical to before (compared as JSON).
  - The run returned to needs-you at pick, `mflow show` listing lane a +2 -0 and lane b +1 -0. `main` stayed at f95d6e8.
- **D.** `follow-up <id> gate@a -- hi` printed `Only a finished Prompt or Judge step of an open run can take a follow-up, and not a step before the candidates split.` and exited 1. `follow-up <id> implement@a --allow Bash hi` printed `follow-up takes no options (use -- before a message that starts with --)` plus usage and exited 64, with no cost.
- **E.** `mflow discard` on all three runs. `git -C repo branch` shows only `main`; no extra worktrees. Only `.flows/` (from my `init-flow`) is untracked in the scratch repo. Nothing outside the scratch directory was touched, and no `mflow` process was left running.

## Not run

- `continuesSessionOf` on a fan-out lane (candidate to candidate), and a follow-up on a step that is itself continued.
- `answer` and `resume`.

## Surprising, though it passed

1. **The follow-up changed the recommendation.** The judge reran and moved from a to b, because lane a now had an extra line that was not part of the haiku. That is the intended effect, but a user sees the recommendation flip after a small request.
2. **The follow-up's first attempt was blocked.** `implement@a` reported that its `echo >>` was blocked by a permission prompt and it fell back to Edit. `follow-up` takes no `--allow`, so a follow-up cannot widen tools. The agent did not leave the file uncommitted, since the engine committed it (555efb2).
3. **A repo node appears in runs of flows with none.** Runs of the sequence flows list a `repo` node that the flow file does not have, and it runs after `second`.
4. **`mflow show` hides costs.** Costs were read from the run files, as `show` has no cost column.
