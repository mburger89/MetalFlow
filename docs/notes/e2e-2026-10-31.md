## Bugs / oddities
1. `mflow launch` stdout is fully buffered when not a tty: with `> file` or `| head`, nothing (not even the run id) appears until exit, so scripted use can't read the id early. (The run id is also the only line before the follow output.)
2. `claude` resolution ignores `PATH` (fixed locations), so tests/e2e can't substitute a fake `claude`. Only a note if that's intended.
3. `mflow init-flow` can't upgrade an old-format `.flows/fix-issue.flow`; no way to regenerate except delete + rerun.
4. An unresponsive `claude` gives no timeout/diagnostic in mflow: node shows `running` indefinitely with no log line. A "no output after N s" hint would help.
